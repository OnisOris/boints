# Rust 3D Algorithm Playground

Компактная оболочка для алгоритмов в физическом 3D-мире: **Rapier3D 0.36.1 + Macroquad 0.4.16**. Алгоритм описывает сцену и выполняет один `update` перед каждым физическим шагом. Окно, физика, рендеринг, камера и интерфейс уже готовы. Версии транзитивных зависимостей закреплены в `Cargo.lock`.

## Запуск на Linux

Нужен актуальный stable Rust (проверено на 1.97.1), X11 или Wayland с XWayland и OpenGL. Обычно достаточно системного графического драйвера; в минимальной Ubuntu могут понадобиться `libx11-6 libxi6 libgl1-mesa-dri`.

```sh
cargo run --locked
# Для оценки скорости используйте release:
cargo run --release --locked
```

По умолчанию 100 агентов. `Algorithm` циклически переключает все обнаруженные алгоритмы. `Play/Pause` останавливает симуляцию; `Step` ставит её на паузу и выполняет ровно один шаг. `Reset` пересоздаёт алгоритм с прежним числом агентов и seed, сохраняя режим паузы. Скорость: 0.25×, 1×, 2×. `Agents −/+` меняет количество от 25 до 200 с перезапуском сцены. Счётчик `objects` включает статические препятствия.

Мышь: левая кнопка и перетаскивание вращают камеру, колесо меняет расстояние. На сенсорном экране: один палец вращает, два меняют расстояние. Жест, начавшийся на интерфейсе, не передаётся камере. `Camera` сбрасывает её, `Grid` переключает сетку. Изменение размеров окна и поворот экрана не перезапускают физику.

## Браузер без Node.js

```sh
rustup target add wasm32-unknown-unknown
./scripts/build-web.sh
cargo run --locked --example serve
```

Откройте адрес, напечатанный сервером. По умолчанию это `http://127.0.0.1:8000/`; если порт 8000 занят, сервер автоматически выбирает свободный порт. Можно задать адрес явно: `cargo run --locked --example serve -- 127.0.0.1:8001`. Локальный сервер написан на Rust со стандартной библиотекой. Для телефона в той же сети запустите `cargo run --locked --example serve -- 0.0.0.0:8000` и откройте `http://<IP-компьютера>:8000/`. Для явно заданного адреса автоматическая смена порта отключена. `file://` не подходит: загрузчик использует `fetch` для WASM.

`dist/` содержит HTML, локальный загрузчик, WASM и его gzip-копию. Все URL относительные, включая работу под `/repository/`. После загрузки приложение не обращается к сети. `.wasm.gz` нужен для измерения/хостинга с подходящей конфигурацией; HTML загружает обычный `.wasm`, а HTTP-сжатие определяет хостинг.

Загрузчик поставляется с MIT-лицензией и одним исправлением ошибки upstream, описанным в [web/LOADER.md](web/LOADER.md). CDN, JS package manager и backend не нужны. JavaScript используется только загрузчиком и для сообщения об ошибке запуска/потере WebGL-контекста. Вся логика сцены, ввода и UI находится в Rust.

## Свой алгоритм: один файл

Создайте `src/algorithms/my_demo.rs`:

```rust
use crate::api::{Algorithm, Color, ObjectId, Sim, Vec3};

#[derive(Default)]
pub struct Demo {
    ball: Option<ObjectId>,
}

impl Algorithm for Demo {
    fn name(&self) -> &'static str { "My Algorithm" }

    fn setup(&mut self, sim: &mut Sim) {
        sim.set_gravity(Vec3::ZERO);
        let id = sim.spawn_ball(Vec3::new(0.0, 5.0, 0.0), 0.5);
        sim.set_color(id, Color::new(0.9, 0.5, 0.3, 1.0));
        self.ball = Some(id);
    }

    fn update(&mut self, sim: &mut Sim, _dt: f32) {
        if let Some(id) = self.ball {
            sim.set_velocity(id, Vec3::new((sim.time as f32).cos(), 0.0, 0.0));
        }
    }
}

pub fn create() -> Box<dyn Algorithm> { Box::<Demo>::default() }
```

`cargo run` автоматически подключит файл. `build.rs` сортирует имена файлов и следит за всей директорией, поэтому добавление, изменение и удаление обновляют реестр. `mod.rs` и файлы с начальным `_` игнорируются; вложенные директории не сканируются. У каждого алгоритма обязательно должна быть функция `pub fn create() -> Box<dyn Algorithm>`: отсутствие или неверный тип даёт ошибку компиляции на месте регистрации. Пустой каталог вызывает объясняющую ошибку сборки. Общий WASM включает все алгоритмы: загрузки нового Rust-кода во время работы нет.

Поскольку модули подключаются сгенерированным `include!`, форматируйте алгоритмы отдельно:

```sh
cargo fmt
rustfmt --edition 2024 src/algorithms/*.rs
```

## Физический API

Везде используется `api::Vec3` (Macroquad), метры и секунды, Y вверх. Преобразования в векторы Rapier скрыты в адаптере.

| Операция | API |
|---|---|
| Динамическая сфера | `sim.spawn_ball(position, radius) -> ObjectId` |
| Статический кубоид | `sim.spawn_box(position, half_extents) -> ObjectId` |
| Положение и скорость | `sim.state(id) -> Option<ObjectState>` |
| Итерация без выделения массива | `sim.states()`, `sim.ids()` |
| Изменение положения/скорости | `sim.set_position(id, p)`, `sim.set_velocity(id, v)` |
| Сила на следующий шаг | `sim.apply_force(id, force)` |
| Гравитация | `sim.set_gravity(Vec3::new(0.0, -9.81, 0.0))` |
| Цвет | `sim.set_color(id, Color::new(r, g, b, a))` |
| Упругость и трение | `sim.set_material(id, restitution, friction)` |
| Удаление | `sim.remove(id)`; для пересоздания снова `spawn_*` |
| Число объектов | `sim.len()`, `sim.is_empty()` |
| Настройки оболочки | `sim.agents`, `sim.time` |
| Прямой доступ | `sim.world: rapier3d::prelude::PhysicsWorld` |

ID принадлежит одному экземпляру `Sim`; не передавайте его в другой мир. В нём есть поколение Rapier и поколение сцены: после удаления или `clear` старый ID не начинает указывать на новый объект. Неизвестный ID даёт `None`/`false`, без паники. Нечисловые скорости, силы и положения отклоняются; неверные размеры при создании тела считаются ошибкой алгоритма и проверяются `assert!`.

Силы суммируются в течение `update`, действуют один шаг, затем оболочка сбрасывает их. `spawn_box` принимает **полуразмеры**, как Rapier. По умолчанию упругость 0.75 и трение 0.45; включён CCD для сфер. В продвинутом алгоритме можно работать с `sim.world.bodies`, `colliders`, joints и другими полями Rapier. Создавайте/удаляйте визуализируемые объекты через `Sim`, иначе для вручную добавленных тел визуализация не появится. При непосредственном изменении существующего тела рендерер использует его действительные положение и вращение.

Оболочка вызывает `update` перед каждым шагом Rapier `1/60 с`. Не вызывайте `sim.step()` из алгоритма. Аккумулятор ограничен восемью шагами; кадры с задержкой более 250 мс отбрасываются. Пауза очищает накопленное время. Неактивная вкладка тормозится браузерным `requestAnimationFrame`; возвращение не приводит к большому догоняющему расчёту. На перегруженном устройстве симуляция может отставать от реального времени, но шаг физики не меняется.

## Проверки

```sh
cargo fmt --check
rustfmt --edition 2024 --check src/algorithms/*.rs
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked --all-targets
./scripts/test-registry.sh
cargo build --locked
./scripts/build-web.sh
# Необязательно: установленный Chromium; тест тоже на Rust
cargo run --locked --example smoke_web
# Только алгоритмы и физика, без графики
cargo run --release --locked --example benchmark
```

Тесты проверяют гравитацию, контакт пола, создание/движение тел алгоритмом, reset и воспроизводимость seed, паузу, одиночный шаг, независимость шага от FPS, защиту от накопления времени, stale handles, одношаговую силу и устойчивость Boids на 1200 шагах. Отдельный скрипт действительно добавляет файл алгоритма, проверяет его регистрацию, удаляет и проверяет исчезновение. Временные файлы очищаются через `trap`. Локально прошли 9 тестов симуляции, тест ограничения путей HTTP-сервера в обоих Rust-инструментах, обе проверки реестра, форматирование, Clippy, нативная и WASM-сборки. `cargo run` действительно открывал окно через X11; запуск завершён ограничением времени через 8 секунд без паники. Браузерный smoke-test после переноса на Rust также прошёл; в `tmp/smoke/result.json` указан `runner: native Rust`.

Smoke-test на Rust запускает временный локальный Rust HTTP-сервер под `/repository/` и headless Chromium с программным WebGL SwiftShader. Проверяет загрузку WASM и ресурсов, отсутствие ошибок консоли, паузу/шаг, переключение сцены, мышь, эмулированные touch/pinch, захват касаний UI и поворот viewport. Скриншоты и JSON сохраняются в `tmp/smoke/`. Это **эмуляция Chromium**, а не тест на Android/iOS или Safari. Если браузер называется иначе, задайте `CHROMIUM=/путь/к/браузеру`.

Python, Vite и Node.js не нужны. Сервер использует только `std`; `base64`, `serde_json`, `tempfile` и `tungstenite` — зависимости только для нативных инструментов проверки (`dev-dependencies`), в приложение и WASM они не входят. Shell-скрипты сборки и CI вызывают Rust/Cargo и системные `cp`/`gzip`; JavaScript остаётся только в браузерном загрузчике и обработке ошибок HTML.

## Измерения и ограничения

Release-профиль: `opt-level = "s"`, LTO, один codegen unit, abort panic, strip. WASM без многопоточной физики. Сферы: 6 колец × 10 сегментов; общий переиспользуемый CPU-меш, ограниченные пачки с u16-индексами. GPU instancing не используется. Macroquad сам группирует геометрию; `touches()` возвращает выделенный список, а текст диагностики использует переиспользуемую строку. Первый кадр может выделять внутренние графические/шрифтовые буферы.

Boids использует переиспользуемый массив позиций/скоростей и простой O(n²) обход соседей. Ограничение UI — 200 агентов. Spatial grid не нужен для измеренной нагрузки, а реальные мобильные пределы предстоит проверить.

Локальные результаты на Intel Core i3-1125G4, Linux x86_64, Rust 1.97.1:

| Алгоритм | Агенты | Алгоритм + Rapier, мс/шаг |
|---|---:|---:|
| Boids 3D | 100 | 0.192 |
| Boids 3D | 200 | 0.632 |
| Bouncing Balls | 100 | 0.413 |
| Bouncing Balls | 200 | 1.168 |

Это средние значения 1200 шагов после 120 прогревочных; они не включают графику и не гарантируют FPS браузера. Headless Chromium 156.0.8078.79 с программным SwiftShader (viewport 1100×760, активная симуляция Boids, окно измерения 2 секунды) в Rust smoke-test показал **28.3 FPS при 100 агентах и 21.7 FPS при 200**; предыдущие прогоны давали 23.3–26.9 / 18.6–20.7 FPS. Это измерение программного рендерера в текущем окружении: цель 60 FPS здесь не достигнута. Цели 60 FPS desktop и 30 FPS mobile требуют измерений на соответствующем оборудовании. Реальные Android/iOS пока не проверены. Высокая плотность пикселей отключена (`high_dpi: false`), MSAA — 1 для уменьшения нагрузки.

Размер текущего `dist/algorithm-playground.wasm`: **1 813 267 байт**; gzip `-9 -n`: **692 415 байт**. Сборочный скрипт печатает точные размеры при каждом запуске. Установленный сервер может отправлять WASM без сжатия.

## GitHub Pages

Один раз в репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**. Затем отправьте проект в ветку `main`:

```sh
git add .
git commit -m "Add Rust 3D algorithm playground"
git push origin main
```

Workflow проверяет форматирование, запускает тесты, собирает нативное приложение, проверяет обнаружение алгоритмов, собирает release WASM и загружает `dist/` через официальный `actions/upload-pages-artifact`. Задание deploy использует `actions/deploy-pages` с `pages: write` и `id-token: write`. Pull request выполняет проверки без публикации. Нужные права предоставляет GitHub, секреты и собственный сервер не требуются.

Адрес для этого репозитория: `https://onisoris.github.io/boints/` — после публикации используйте фактический URL из задания deploy. Workflow следует [официальному механизму Pages Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages). Настройка workflow выполнена локально; push и успешный deploy в рамках разработки не выполнялись и не подтверждены.

API сверены с исходниками закреплённых crates и официальной документацией: [Rapier PhysicsWorld](https://docs.rs/rapier3d/0.36.1/rapier3d/pipeline/struct.PhysicsWorld.html), [Macroquad](https://docs.rs/macroquad/0.4.16/macroquad/).
